# MVP 规格

状态：执行提案。不是功能已实现清单。

## 第一条用户故事

使用 DSH 的用户选择一个已启动的测试应用，批准插件读取和在明确窗口内编辑测试内容。Agent 观察当前 UI，修改准确目标，回读新值，并报告证据。用户能看见目标与状态，并能阻止后续动作。

## 必需能力

1. 发现运行应用，不读取未授权应用 UI。
2. 取得 read 许可后获取有界 AX 观察。
3. 用可信 host 上下文创建限定 app/window 的控制任务。
4. 对目标句柄执行 press、set_value；键盘输入作为独立受控能力。
5. 执行前重新验证目标与任务许可。
6. 返回阶段准确的动作回执和新观察。
7. 通过 readback 验证字段值或 fixture 状态。
8. 有独立于模型的暂停、取消与紧急停止入口。
9. 截图显式请求，日志不留私人输入原文，artifact 可按范围清理。
10. 停用插件时注销工具和 UI、撤销授权、取消 native 工作并安全释放。

## 不属于语义 MVP 的能力

- 视觉 grounding、任意坐标点击、滚动、拖拽。
- 复杂富文本、任意快捷键、无人值守跨应用长流程。
- 远程桌面流、漂亮光标动画、模型训练。
- 真实高影响业务动作。

这些能力通过 P1 或单独规格扩展，不能为了演示绕过门槛。

## 三个发布切片

### Alpha A：语义 fixture 闭环

CU-000 至 CU-017 的 P0 依赖完成。只在 fixture 验收。UI 与 native 故障回执可观察。不能宣传任意真实应用兼容。

### Alpha B：有限真实应用试用

再完成 CU-018、CU-019、CU-020 和 CU-024 至 CU-028。只使用用户明确批准的测试文档和测试应用。兼容性声明按应用版本和模式列出。

### P1：视觉与 pointer 扩展

CU-021 至 CU-023 单独验收。不通过定向输入门槛就不开放 pointer。P1 失败不应让 AX P0 回退成全局输入。

## 成功与失败

- 目标错、越权输入、全局指针输入、批准复用、机密日志泄露：发布阻断。
- 目标应用拒绝后台输入并明确报告 unsupported：允许的产品结果。
- 动作可能执行但结果无法确认并报告 unknown：允许的诚实结果，但必须留证据且不能自动重试。
- 工具 completed 后模型误报业务成功：模型层验收失败，需要调整工具描述、Skill 或证据表达，不能隐藏回执。
