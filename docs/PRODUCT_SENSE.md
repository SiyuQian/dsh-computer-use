# 产品定义

## 已确认方向

用户已在本会话同意以下定义：

> 一个 macOS 原生、模型无关的 DSH Computer Use 插件。语义目标优先，执行前重验，默认后台协作，风险受控，结果有证据，用户随时能接管。

用户随后要求详细执行计划，并指定 SiyuQian/dsh-computer-use 说“开工”。2026-11-09 另行要求创建 PR，授权现有实现的提交/开发分支推送，并为原空仓库建立无功能文件的 main 审查基线；未授权合并、安装到日常 Profile、软件发布或控制私人应用。

## 目标用户与问题

初期目标用户建议限定为：使用 DSH 的开发者和需要操作 GUI-only 原生应用的技术用户。该细分来自前文提案，尚无独立用户访谈证据。

要解决的问题：通用模型会调用工具，但无法可靠知道当前输入会落在哪个对象、旧状态是否还能使用、操作是否真实生效，以及用户何时想接管。

产品应让用户能回答三个问题：

1. 它正在操作哪个应用和窗口？
2. 它不确定时会不会停？
3. 它说完成时，有什么证据？

## MVP 建议边界

- 只支持真实 macOS 应用；最低版本建议 macOS 14+，需 CU-001 核实实际 API availability。
- 一个宿主实例同一时刻只执行一个原生变更动作。
- 一个控制任务默认只绑定一个应用进程和一个窗口。
- 首条纵向切片使用自有 AppKit fixture，不操作用户已有账号或文档。
- 支持语义控件操作、目标绑定文本输入、受限快捷键、观察与有界等待。
- 截图按明确请求获取，默认不自动持久保留。
- 后台模式不得静默切前台；前台模式必须单独获准。
- 视觉定位、坐标 fallback、滚动和拖拽作为后续 P1 能力，不阻塞语义 MVP。

以上是计划建议。CU-000 将用户批准的变更记录为范围决策。

## 非目标

- 不训练自有视觉模型。
- 不实现任意脚本、AppleScript、JXA 或 shell 的 computer-use 后门。
- 不替代已有 API、CLI、专用插件和浏览器 DOM 自动化。
- 不承诺所有应用能后台输入。
- 不自动化付款、真实发信、不可逆删除、账户安全或系统权限审批。
- 不承诺 UI 能力等同文件沙箱，也不承诺所有行为能回滚。
- 不在 MVP 支持 Windows 或无人值守跨应用长任务。

## 用户可见质量门槛

- 明确显示目标、模式、控制任务和当前状态。
- 用户可停止新动作，插件安全释放已按下的键或鼠标。
- 未确认状态、未知效果与失败分别呈现，不用统一 success 掩盖。
- 不把“事件已发送”当“业务已成功”。
- 所有支持声明必须关联实际运行的测试记录。

## 差异化

重点不是“独立鼠标”。Claude 与 OpenAI 的 Mac 产品也已公开后台能力。重点是执行契约透明、目标绑定、风险策略可审计、结果证据与 DSH 工作流组合。
