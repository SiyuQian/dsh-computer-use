# 插件实施设计

状态：目标设计。用户已指定仓库并授权实施。contracts 与 host-adapter 已有基础子集，实际存在模块见 [当前架构](<../../ARCHITECTURE.md>)；其它域不能据本设计视为已实现。

## 1. 先冻结三个边界

1. **宿主边界**：插件只能使用 CU-001 证实存在的 DSH 插件、工具、审批、会话、子进程和 UI 扩展接口。不修改 DSH Core。
2. **执行边界**：原生 helper 只接受版本化、封闭的动作协议。它不是脚本执行器。
3. **授权边界**：模型提出任务和动作。宿主取得 Agent、Session、workspace 和用户许可。模型不能创建自己的控制授权。

## 2. 建议模块

以下是实施落点建议，不是当前存在的路径。CU-002 可以根据目标仓库调整名称，但不得混合职责。

| 模块 | 职责 | 可以依赖 | 禁止 |
|---|---|---|---|
| contracts | 请求、结果、错误、版本及运行时校验 | 最小 schema 库 | DSH、原生输入、UI |
| observation | 观察生命周期、投影、目标描述、句柄 | contracts、backend 接口 | 直接触发输入 |
| policy | 应用许可、任务边界、风险下限、单次批准 | contracts、宿主授权适配器 | 信任模型 sensitive=false、调用原生输入 |
| coordinator | 控制权、串行化、幂等、取消、阶段状态 | contracts、时钟、policy | 依赖 UI 判断是否已执行 |
| evidence | 动作证据、回读、artifact 生命周期、隐私投影 | contracts、backend 观察接口 | 从树变更推断所有业务成功 |
| service | 按固定顺序组合上述模块 | 各域接口 | 私自添加第二条无策略输入路径 |
| backend/macos | 封闭协议客户端、能力检测、helper 生命周期 | contracts、DSH 子进程适配 | 接受任意命令或全局输入兜底 |
| host-adapter | DSH 注册、可信调用上下文、审批和服务生命周期 | service、已证实 SDK | 把模型参数当身份 |
| client-ui | 目标状态、模式、批准摘要、停止、诊断 | 宿主鉴权后的 RPC | 直接调用 helper、自己批准动作 |
| native-helper | AX 观察、目标重验、受限输入、安全释放 | macOS API | 自行扩大授权范围或执行源代码 |
| fixtures/tests | 可复现 AppKit UI、时钟、transport 故障注入 | 测试工具 | 借用用户私人应用进行默认测试 |

service 是组合层。域模块之间避免循环引用。依赖规则必须由 CU-002 建立边界测试，不靠目录名称自证。

## 3. 两条数据路径

### 观察

可信调用上下文 → read 权限 → 精确进程/窗口 → 有界 AX 读取 → 安全字段投影 → 句柄生成 → 可选截图 → 观察回传。

### 变更动作

可信上下文 → schema 校验 → 控制任务 → 宿主风险判断 → 必要审批 → 控制锁 → 新鲜目标重验 → 批准摘要再校验 → 消费一次性批准 → 原生 helper 最后重验 → 一次执行 → 回读证据 → 精确回执。

等待审批时不要持有输入锁。审批完成后必须重新取得锁并重验。变更动作与取消的并发语义见 [接口约定](<contracts.md>)。

## 4. 原生能力逐步开放

### P0：AX 语义执行

先实现 AX 观察、AXPress、可编辑值设置及明确控件的输入回读。若原生字段不支持安全写入，则报告 unsupported。不要为了演示成功自动选择键盘 fallback。

### P0 受控扩展：明确目标的键盘

只有显式启用且已测试的目标应用，才允许背景定向键盘路径。执行前和首个按键前再次核对 pid/window/focused target。每个 down/up 必须配对。收到停止或错误后释放受管按键。

### P1：坐标与拖拽

必须先通过 CU-022 的定向输入能力门槛：系统光标不移动、前台不改变、无全局 pointer route、目标窗口不能歧义。SPI 不可用就关闭该能力。

模型参数不能把后台路径升级为全局输入。视觉只能提出点位，不是可认证身份。高影响像素操作超出 MVP。

## 5. 用户协作模式

- `background`：默认。禁止主动 activation 和系统光标移动。接受能力限制。
- `takeover`：需要单独用户批准并显示作用范围。切前台也只能作用于获准目标。不能把它解释为允许任意全局输入。
- 全宿主实例一次只有一个变更动作在 native 阶段。
- 跨会话控制任务默认独占同一目标窗口，等待或拒绝策略必须显式。
- 自有用户输入监测若可用，可暂停动作。监测不可用或存在竞态时，不能声称完全无竞争。后台键盘/拖拽应关闭或要求接管。
- 多个 DSH host 进程不在一个内存锁内。CU-010 必须实现每 OS 用户的唯一控制 broker/系统锁；无法确认唯一控制器则禁止 native 变更。

## 6. 最小设置界面

P0 只需要目标、模式、控制任务有效期、权限来源、当前执行阶段、暂停/停止和能力诊断。截图默认关闭，模式默认 background。

审批摘要来自 canonical action 与可验证目标元数据，不只是模型提供的 reason。reason 可展示，但必须明确是模型解释。

不要先做漂亮光标动画、复杂仪表盘或远程桌面直播。

## 7. 复用策略

参考插件使用 MIT。建议在 CU-000 选择以下一种路线并记录：

- fork 后独立品牌与持续同步，保留许可。
- 在新仓库复用经审查的 resolver/helper 模块，保留来源与测试。
- 独立实现，但仍以相同反例和 native 验收门槛测试。

不要把复制代码称为 clean-room。不要先重写全部原生输入以追求“自己的代码”。不要在评估用 checkout 中实施新产品。

## 8. 必须明确的能力上限

- AX 语义稳定不代表业务上下文未变。窗口标题或控件名字不能认证账户和收款对象。
- 执行前重验与输入不是系统级原子事务。对纯坐标目标不能声称绝对防 TOCTOU。
- UI 访问不是 workspace 文件沙箱。获准应用已有的文件与网络能力仍然存在。
- 同一 OS 用户的任意恶意原生代码不属于插件内逻辑授权能完全隔离的威胁。
- 私有 SPI 不可用不阻塞语义 P0，但必须使相关 pointer 能力 unavailable。
